# World Builder 封包身份、预览格式与仓库不同步

## 客观事实

- 曾出现编辑器源 SGB 与 Git 中 SGB 不同哈希，导致另一台电脑接续到旧地图。
- 仅修改 `.info` 显示名会让 basename、场景内部身份和封包 TOC 不一致，地图可能被索引器跳过。
- 384 × 384 俯视截图不能直接作为 320 × 320 地图的 `_mm.tga`；运行时产物要求 768 × 768、32-bit 未压缩 BGRA、alpha 全 255。
- 把预览留在本机 `artifacts/` 而未放进仓库 `evidence/`，等于没有交付预览。

## 根因

- 将“保存源文件、生成 sidecar、封包、同步仓库、发布证据”当成相互独立的步骤，缺少同一版本身份和字节一致性检查。

## 固化流程

1. 关闭游戏和重复的 World Builder 进程，保持单写者。
2. 以同一个 basename 保存完整九文件场景 bundle，不手工单改 `.info` 身份。
3. 生成合规 `_mm.tga` 后封包，并执行 `Archive.exe -t` 与 `-l`。
4. 将源 bundle、SGA 和全局 PNG 预览复制到仓库固定目录。
5. 对源目录与仓库九文件逐项核对 SHA-256；运行目录与仓库 SGA 也必须同哈希。
6. 提交前检查 Git LFS 状态，并确认 README 直接引用 `evidence/` 预览。

## 本轮验证

- v6 九文件源目录与仓库逐项同哈希。
- v6 运行目录 SGA 与仓库 SGA 同哈希，且归档自检通过。
- `evidence/overhead-v6.png` 已作为 Git 可渲染全局预览纳入交付。
