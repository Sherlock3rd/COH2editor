# COH2 地图快速生产规范

生产阶段与退出条件以 `production-gates-spec.md` 为准。本规范规定快速完成的执行顺序和资源分配。

## 顺序

1. 先画路线、点位、领地和基地关系图。
2. 创建独立 `2p_` 场景目录与同名 `.sgb`。
3. 生成并摆正双人起始包。
4. 放置 VP、燃料、弹药和标准领地点。
5. 完成领地/补给连接、可玩边界和三路通行。
6. 用最低限度道路、掩体、LOS blocker 完成灰盒。
7. 进入游戏做 1v1 AI 运行验收。
8. 灰盒通过后再制作高度、地表、道路 spline、建筑、植被和灯光。
9. 每轮重大美术或路径变化后回归游戏内验收。

## 效率规则

- 复用生成的完整起始包，不手工重建已有对象。
- 使用网格、可玩区显示、领地颜色开关和模式快捷键。
- 重复墙、道路和物件优先使用 spline、复制与批量选择。
- 高度图和高成本建筑晚于可玩灰盒。
- 出现编辑器内存/错误趋势时立即保存并重启，避免长时间带错操作。
- 同类 gameplay 对象一次选中、批量放置、汇总复核；不得逐点重复展开对象树。
- 只有模态窗口、编辑模式、镜头或窗口状态改变后才强制重新观察；连续同类放置不逐次截图。
- 同一 UI 操作连续失败两次必须换用可访问性导航、键盘、筛选或其他已验证路径。
- G6 前，不能直接解除当前阻断的脚本、文档和美术工作全部后移。
- 状态汇报使用 G0–G7，并明确最后保存阶段和未保存操作。

## 快速灰盒关键路径

`G0 场景正确 → G1 点位完整 → G2 领地连通 → G3 三路可走 → G4 边界有效 → G5 最小战斗灰盒 → G6 产物通过 → G7 游戏内通过`

任何工作若不能推进下一个阶段或解除其阻断，不得占用当前关键路径。

## UI 放点可重复性要求

- 相机、缩放、卷展栏或窗口尺寸改变后，不得复用上一视图的像素坐标。
- gameplay 点以 `1 个实体 + 1 个新 sector + 1 次处理数验证` 为最小可验证单元。
- 批处理只能在已实测返回数与输入数相等时使用；否则强制回退到原子事务。
- G1 不能仅以右键操作次数验收；必须以实际实体信息或新 sector 处理数验收。

- 不以“已保存文件”替代“已生成可运行场景”。
- 不以“有双人出生位”替代“有完整对局结构”。
- 不以“编辑器无报错”替代“游戏内加载、路径与规则验收”。
- 不在核心领地和路线未定前投入大量装饰。
- 不以“尺寸已修正”“World Builder 已打开”“自动出生包已生成”替代 G1 及更高阶段。
- 不把未保存的 UI 操作写入已完成清单。

## 灰盒视觉与自动化验收要求

- 自动化点击字段必须符合 Computer Use API：右键为 `mouse_button`，多击为 `click_count`，拖动为 `from_x/from_y/to_x/to_y`。
- 道路必须使用独立纹理层绘制，不允许通过替换唯一底层伪造道路完成度。
- 全局视图至少能直接辨认一条贯通主路、左右翼机动回路、中心交战区、两侧掩体/林带分布。
- 任何批量放置后必须打开 `OBJ` 可见性并进行一次全局截图；没有视觉反馈的批量操作不得计入完成结果。
- 保存前必须清零重复 sector creator；清理时按类型过滤并以错误列表中的实体 ID 为删除依据。
