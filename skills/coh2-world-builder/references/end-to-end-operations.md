# World Builder 端到端操作手册

本手册封装从接管现有场景到交付可玩 1v1 灰盒的完整操作。执行时以 `spec/coh2-world-builder/` 为结果标准；本文件只规定操作方法和效率约束。

## 0. 先定义本轮最小交付

默认最小交付是“可运行灰盒”，不是“文件能打开”或“编辑器里有地形”。进入 World Builder 前先记录：

- 正式场景名、游戏安装路径、实际 `Data\Scenarios` 路径。
- 地形尺寸、可玩区尺寸、玩家数、出生方向。
- VP、燃料、弹药、标准领地点数量与坐标表。
- 三条主路线、sector 数量、补给邻接关系。
- 本轮停止点：至少完成哪一个生产阶段。

非必要文档、脚本优化和美术细化不得抢占灰盒关键路径。

## 1. 接管、审计和备份

1. 运行环境检查，确认 `WorldBuilder_CoH_2.exe`、游戏程序和目标目录存在。
2. 将场景视为不可拆分 bundle，检查同名 `.sgb`、`.info`、`.options`、`.scenariomarker`、`_ID.scar`、`_mm.tga`、`_tdm.dds`、`_lao.dds`。
3. 使用 `scripts/sync-map-scenario.ps1` 同步完整 bundle；目标内容不同则停止，除非用户明确授权覆盖。
4. 修改已有正式场景前，按时间戳备份完整 bundle，并记录 SHA-256。
5. 打开后立即审计真实数据，不以文件名或截图推断内容：
   - `.info` 中的可玩区尺寸和玩家点位；
   - World Builder 标题栏中的实际场景；
   - 起始包、目标点、资源点、领地点、sector 和边界；
   - Error Messages 与日志中的阻断项。

若实际场景与已确认设计不一致，先备份，再按授权重建；不得把错误资产继续包装成“完成”。

## 2. 新建或重建多人场景

1. `File > New Multiplayer Map`。
2. 默认选择 Blank Terrain，地形 `384 x 384`，可玩区 `320 x 320`，cell `1.0 m`。
3. 勾选 Generate Starting Positions，玩家数设为 2。
4. 以正式 `2p_` 名称保存到独立同名目录；场景目录和 `.sgb` basename 保持一致。
5. 保存后从文件系统复核 `.sgb` 与 `.info` 的时间戳、尺寸和生成产物。

自动生成的出生包只是起始素材。默认生成位置不代表设计位置，必须整体移动并验证玩家归属、基地出口和进入点。

## 3. UI 操作与批量放置策略

### 3.1 先建立坐标映射

1. 切换到 Object Placement。
2. 缩放到完整地形可见，开启可玩区和网格 overlay。
3. 用地形四角、中心和已知对象建立“地图坐标 → 屏幕坐标”映射。
4. 先用一个可撤销或容易识别的对象验证方向、比例和坐标原点，再批量操作。

不得在未确认坐标映射时连续放置正式点位。

### 3.2 对象树和放置顺序

在 `ebps > gameplay` 中按以下固定顺序选择并批量放置：

1. `victory_point`
2. `territory_fuel_point_mp`
3. `territory_munitions_point_mp`
4. `territory_point_mp`

同一对象类型应一次选中、连续放完，再进行一次复核；不要每放一个对象就重新展开目录或截图。

对象树难以定位时，依次采用：可访问性元素、树键盘导航、筛选框、滚动条。只有前三种不可用时才使用像素坐标；坐标点击前必须重新获取窗口状态。

### 3.3 出生包

- 选择完整生成包并整体移动到规划起点，避免逐个重建。
- `starting_position_shared_territory`、`starting_territory_team`、基地圆、`map_entry_point` 保持同组。
- 两个起点使用不同玩家/队伍归属；基地出口朝向可玩区，禁止被单个物件封死。

## 4. 灰盒关键路径

严格按生产顺序推进，每阶段达到退出条件才进入下一阶段：

1. **G0 场景正确**：名称、路径、尺寸、玩家数正确，完整 bundle 可保存和重开。
2. **G1 点位完整**：2 个完整出生包、3 VP、设计数量的燃料/弹药/标准领地点全部落位。
3. **G2 领地连通**：sector 覆盖可玩区，双方 HQ 到自然资源的补给链成立，cutoff 可反制。
4. **G3 路线可走**：中心、左翼、右翼三路明确；基地出口、步兵和中型车辆主路径无阻断。
5. **G4 边界有效**：soft map、interactivity stage 5、impass map 一致，单位不能离开可玩区。
6. **G5 最小战斗灰盒**：道路、少量掩体和 LOS blocker 能表达三路职责，无详细装饰。
7. **G6 编辑器与产物通过**：保存、重开、错误列表无阻断，所需 sidecars 和战术图生成。
8. **G7 游戏内通过**：真实 1v1 对 AI 完成出生、占点、资源、VP、AI 和车辆路径检查。

状态报告必须使用上述阶段编号，并说明“已通过”和“未通过”；不得使用含糊的“基本完成”。

## 5. 保存、生成和恢复

- 在 G0、G1、G2、G4、G6 分别保存一次；每次保存后检查文件时间戳和日志。
- World Builder 发生内存或错误趋势时，先保存、关闭、重开，不在带错状态下长时间编辑。
- 若打开时崩溃，先查同名 `.info` 和 sidecars 是否缺失，再查日志，不要反复盲目启动。
- 若 UI 自动化检测到用户输入或 Escape，立即停止输入，记录最后完成的阶段和“已保存/未保存”状态；恢复前重新获取窗口、标题、模式和当前选择。
- 恢复后不得沿用旧截图 ID、旧控件索引或旧坐标。

## 6. 效率预算

- 关键路径优先级：地图可玩性 > 场景产物 > 交付自动化 > 文档 > 美术。
- 一类重复对象只做一次选取、一次批量放置、一次汇总检查。
- 模态窗口、模式切换、地图缩放或窗口遮挡后才强制重新观察；普通同类批量放置不逐次截图。
- 同一 UI 操作连续失败两次，立即换策略，不再重复像素试探。
- 任何辅助脚本如果不能直接解除当前阻断，应推迟到 G6 之后。
- 在 G7 通过前，所有对外表述必须是“规划”“骨架”“灰盒进行中”或具体阶段，不得称为“可玩地图”。

## 8. World Builder 点位原子事务（实测固化）

- 缩放、相机角度或右侧卷展栏变化后，旧的屏幕坐标映射立即作废。必须用当前地形四角、中心和一个已知实体重新标定，再放正式点。
- `Object Placement` 中的树项要双击才能稳定地重新武装放置。只改变单击高亮不能证明下一次右键会生成新实体。
- 旧版 World Builder 对同类 gameplay 点的快速重复放置会吞操作。安全路径是原子事务：`切回 Object Placement -> 双击树项 -> 右键放 1 点 -> 切 Territory Editor -> Add territory under new Points -> 确认返回 1 New points processed`。
- `Add territory under new Points` 是 gameplay 点保存的前置依赖。新点未拆出 sector 时直接保存，会触发 `More than one sector creator entity found` 并拒绝保存。
- 每次原子事务后记录处理数；只有返回 `1` 才计入完成数。返回 `0` 表示该点未新建或已处理，必须用选择信息/坐标复核。

交付时分别记录：

- 编辑器证据：标题、路径、尺寸、点位、领地图层、边界、错误列表。
- 产物证据：bundle 文件清单、时间戳、构建/同步结果。
- 游戏内证据：自定义房间、双方开局、占点与资源、VP drain、AI 行为、步兵和车辆路线。
- 未完成项：明确列出阶段编号、风险和下一步，不用成功的低阶段证据替代高阶段验收。

## 9. 2026-08-20 高速灰盒制作与排错

- Computer Use 的右键参数必须使用 `mouse_button: "right"`，双击次数必须使用 `click_count: 2`；`button`、`clickCount` 会被忽略，表现为光标移动但不放置实体。
- 地表纹理不能在唯一底层上直接 `Assign` 后期待局部绘制；正确顺序是：保留底层、点击 Layers 的新增按钮创建第二层、为上层分配道路纹理，再在上层拖动画笔。
- `sky.drag` 使用 `from_x/from_y/to_x/to_y`。主路先一笔贯通，再补左右翼闭环；每一轮结束立刻缩放到全局检查可辨识度。
- Object Placement 中先确认资源树仍处于目标目录，再双击叶节点并用右键放置。资源树滚动后不能复用旧行坐标。
- 顶部 `OBJ` 是物件可见性开关；放置后全局看不到实体时，先检查该开关，不要重复放置。
- 保存弹出 `More than one sector creator entity` 时，启用 Selection Information 的 Filter，按 `victory_point` 或 `territory_point_mp` 过滤；点击点位读取实体 ID，只删除错误列表明确列出的重复 ID，然后立即重新保存。
- 保存成功的判据是：`Map Setup Errors`、`Failed to save scenario`、`Error Saving file` 三层提示均未出现；第一层提示关闭后仍需等待后续错误提示。
- 屏幕拖动、移动 gizmo 或光标位置不能证明实体坐标已改变；必须用 Selection Information、保存后的 `.info` 或二进制实体坐标复核。
- 删除 sector creator 后必须先执行 `Convert empty territory to null`，再保存；否则残留空 sector 会造成颜色分区和昨夜版本不一致。
- 普通 Save 禁用或无写入时，使用 Save As 生成新 basename；重新打开新文件并通过 Territory Editor 处理数、`.info` 与时间戳验证后，才可作为规范版本。
- 二进制修复只能用于恢复明确坐标或复制已知实体模板；修复后必须立即由 World Builder 打开并 Save As 规范化，不能直接把手工修改的 `.sgb` 当最终交付。
