# World Builder 制作迟缓且误判里程碑

## 基本信息

- 日期：2026-08-19
- 分类：execution / prioritization / world-builder
- 关联需求：`2p_codex_crossroads` 快速完成

## 客观事实

- 工作时间被仓库检查、同步脚本、文档和逐点击截图大量占用，地图核心灰盒推进不足。
- 首轮只验证“场景能打开”，没有先核对尺寸、出生点、三路结构和资源数量。
- 实际场景为 `160 x 128`，与已确认的 `384 x 384` 地形、`320 x 320` 可玩区方案不符。
- 进入 World Builder 后边操作边摸索对象树、滚动、镜头和坐标映射，产生重复失败操作。
- 没有以“出生点 → 目标/资源 → 领地 → 三路 → 边界 → 游戏内测试”为唯一关键路径。
- 自动化检测到用户输入后必须停止，未保存的批量放置因此不能作为完成证据。

## 原因判断

- 将环境与交付管线工作置于可玩灰盒之前，优先级倒置。
- 未设置可观察的生产阶段和阶段退出条件。
- 对重复对象采用逐项确认，而非一次选取、批量放置、汇总验证。
- 同一 UI 导航方式失败后仍继续像素试探，没有及时切换到筛选、键盘或可访问性操作。
- 把“能打开”“已保存”“尺寸正确”等低阶段结果误当成接近完成。

## 修复方案

- 在 Skill 中新增端到端操作手册、G0–G7 阶段、UI 批量策略和效率预算。
- 在快速生产 Spec 中加入关键路径、时间盒和禁止伪进度规则。
- 在验收 Spec 中要求每次状态报告同时标注阶段、保存状态和证据类型。
- 地图达到 G6 前推迟非阻断脚本与详细文档；达到 G7 前不得称为可玩。

## 防呆清单

- [ ] 当前动作是否直接推进下一个灰盒阶段？
- [ ] 是否已先核对真实尺寸、对象数量和地图内容？
- [ ] 同类对象是否一次选取并批量放置？
- [ ] 同一 UI 操作失败两次后是否切换策略？
- [ ] 是否明确记录最后保存阶段和未保存操作？
- [ ] 是否把编辑器、产物和游戏内证据分开陈述？
